# CAT Tools Diagnostics — Trados Studio & memoQ on Wine

**الحالة:** وثيقة معرفة تشخيصية موثقة المصادر — ليست وعد توافق.
**المصدر:** جلسة مراجعة خارجية (DeepSeek، 2026-11-11، الدور 6) بحثت في 38
مصدرًا عامًا شملت قاعدة WineHQ، وقُدمت توصياتها هنا بمنهجية «الدمج الذكي»
الموثقة في `docs/reviews/EXTERNAL_REVIEWS.md` (القسم 8).

---

## 1) الواقع الموثق: التطبيقان على Wine

| التطبيق | الحالة الموثقة | المرجع |
|---|---|---|
| Trados Studio | غير مدعوم رسميًا على Wine؛ تقارير تعطل موثقة (مثال: Trados 2019 يرمي backtrace عند التشغيل)؛ نجاحات جزئية لإصدارات أقدم عبر winetricks (.NET + VC++) | WineHQ bug 48152، 13679، 9433 |
| memoQ | الدعم الرسمي يوصي بـ memoQWeb أو جهاز افتراضي؛ المحاولات عبر Wine تفشل عند بدء التشغيل حتى مع تثبيت .NET مسبقًا؛ نجاحات جزئية عبر أدوات مساعدة | WineHQ bug 56929 |

**خلاصة صادقة:** لا توجد حزمة «تعمل بسلاسة» لأي منهما؛ كلاهما تطبيق .NET
ثقيل والعقبة الأساسية هي التوافق ذاته لا أدوات التشخيص. هذا المشروع
نظام تشخيص محلي (offline-first) — دوره فهم سبب الفشل لا تثبيت التطبيقات.

## 2) الاعتماديات الموثقة (من تقارير الفشل أعلاه)

| المكون | ملاحظات |
|---|---|
| .NET Framework | إصدارات مختلفة حسب الإصدار (2.0 قديمًا، 4.x/4.8 حديثًا)؛ تثبيت عبر winetricks |
| Visual C++ Redistributable | 2005 و2010 و2015–2022 غالبًا مطلوبة معًا |
| DLL تراثية | msvcr70.dll / fusion.dll لبعض الإصدارات القديمة (فشل تسجيل التجميعات موثق في 9433 و13679) |

## 3) ما أضافه المشروع من هذه الجلسة

### 3.1 طبقة تلميحات CAT (`src/wine_ai/diagnostics/cat_tools.py`)

- توقيعات فشل موثقة (mscoree.dll، 0x80131700، fusion.dll، msvcp/vcruntime،
  msvcr70/71) تُحوَّل إلى تلميحات دقيقة: `dotnet_runtime_missing`،
  `assembly_load_failure`، `vc_runtime_missing`، `legacy_dll_missing`.
- **التلميحات لا تدخل مخزون المعرفة:** عمود `error_category` مقيد بـSQL
  `CHECK` في المخطط v3 (`missing_module/graphics/memory/startup/unknown`)
  واستقرار المخطط قرار موثق؛ التلميحات طبقة فرز فقط.
- المواد الخام للسجل لا تغادر الوحدة أبدًا؛ المخرجات أسماء تلميحات
  وأعداد تجميعية وسلاسل ثابتة.

### 3.2 أمر التشخيص بوضع CAT

```
wine-ai diagnose --log FILE --profile trados   # أو memoq
```

- يعيد إثراء نتائج التشخيص العامة بتلميحات CAT ومراجع WineHQ ذات الصلة.
- في JSON: مفاتيح `profile` و`profile_hints` (تظهر فقط عند نجاح قراءة السجل).

### 3.3 تكامل winetricks — اقتراح حصرًا

عند اكتشاف توقيع مفقود، يطبع الأمر أمر winetricks المقترح مثل
`winetricks dotnet48` أو `winetricks vcrun2005 vcrun2010 vcrun2022`
مسبوقًا بعلامة **«suggestion (NOT executed)»**:

- **لا ينفذ المشروع winetricks أبدًا** — سياسة «لا إصلاح تلقائي»
  (AGENT_POLICY) وقائمة السماح في `command.py` لم تُمس.
- المستخدم هو من يختار الفعل المطابق للمكوّن المفقود فعليًا ويشغّله يدويًا
  في بيئة Wine نظيفة مخصصة.

## 4) سير العمل الواقعي الموصى به

1. بيئة Wine نظيفة مخصصة (لا `~/.wine` — محمية دائمًا في هذا المشروع).
2. تثبيت الاعتماديات يدويًا عبر winetricks وفق الجدول أعلاه.
3. عند الفشل: جمع سجل التشغيل ثم `wine-ai diagnose --log ... --profile ...`
   لفهم الطبقة الفاشلة (.NET؟ VC++؟ تسجيل تجميعات؟).
4. بديلان موثقان عند الاستحالة: memoQWeb، أو آلة افتراضية، أو CrossOver
   (خيار تجاري يقدم دعمًا أفضل من Wine الخام) — خارج نطاق هذا المشروع.

## 5) تصنيف الأدلة

| الادعاء | التصنيف |
|---|---|
| عدم الدعم الرسمي والتقارير الموثقة للتطبيقين | PROVEN (مصادر عامة: WineHQ ووثائق البائع) |
| فائدة خريطة التوقيعات في فرز السجلات | PARTIALLY_PROVEN (اختبارات وحدة على سجلات اصطناعية؛ لا تقييم ميداني بعد) |
| أوامر winetricks المقترحة تحل فشلًا معينًا | UNPROVEN — اقتراحات فقط، تُتحقق يدويًا لكل بيئة |
