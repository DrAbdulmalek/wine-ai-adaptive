## وصف المشروع

مكتبة تشخيص محلية (local-first) لتطبيقات Wine على Linux، مبنية فوق SQLite
بتصميم مُحصّن يقبل البيانات المنظمة فقط ويمنع تخزين أي محتوى خام. المبادئ
الثابتة: **offline-first، مكتبة Python القياسية فقط (لا اعتماديات خارجية)،
fail-closed، لا root، لا سحابة، MIT**.

## الحالة الراهنة (فاعلمها كمرجع — لا تدّعِ معرفة بما لم أرسله)

- الإصدار 0.2.0 (على PR #4 المفتوح، فرع `feature/deepseek-review-enhancements`، مبني فوق فرع PR #3).
- مخطط قاعدة البيانات v2: عمودان اختياريان `error_code` و`prefix_id` مع ترحيل ذري fail-closed من v1.
- طبقة استعلام للقراءة فقط: `find_by_error_category` / `find_by_gpu_vendor` / `find_by_evidence_status` / `find_by_error_code` / `category_counts` / `correlate_error_codes`.
- `diagnostics/codes.py`: استخراج وتصنيف رموز الأخطاء (HRESULT/NTSTATUS/Win32) دون تخزين نص خام.
- `gpu_compatibility/vendor_data.py` + `data/vendor_map.json`: معرفة ثابتة مرفقة لمورّدي GPU.
- `environment/snapshot.py`: لقطات بيئة للقراءة فقط (كشف المشغّل Steam/Lutris/Bottles/Heroic، اسم بادئة مجرد فقط).
- `cli.py`: أداة `wine-ai status` للقراءة فقط. 108 اختبارًا ناجحًا على Python 3.11/3.12/3.13.
- PRs مفتوحة: #2 (توثيق أمني)، #3 (استعادة المكونات الأصلية حرفيًا)، #4 (تحسينات المراجعة الخارجية، يشمل تعديلات #3).

## قواعد ملزمة لك (سياسة الوكلاء في docs/AGENT_POLICY.md)

1. **لا تطلب مني توكن في نص المحادثة إطلاقًا**، ولا تكتب أي سر في الملفات. أي توكن ظهر في محادثة يُعد مكشوفًا — ذكّرني بإلغائه.
2. أنت **لا تملك حق الدمج**: لا دمج في `main` ولا دفع مباشر إليه ولا force-push ولا إعادة كتابة تاريخ. مخرجاتك تصل عبر فرع + PR أقترحه أنا.
3. لا تغيّر الترخيص (MIT)، ولا إعدادات المستودع أو Actions أو الأسرار، ولا تنشئ Releases أو Tags.
4. لا ترفع أي بيانات مستخدم حقيقية: لا `*.sqlite3` ولا ملفات جانبية ولا EXE/DLL ولا محتويات Wine prefix ولا سجلات شخصية. الاختبارات على `TemporaryDirectory` فقط.
5. لا تضف اعتماديات خارجية ولا تستدِ خدمات شبكية؛ كل جديد مكتبة قياسية وoffline.
6. لا تُعدل كتابةً المكونات الأصلية المستعادة حرفيًا (`evidence.py`, `command.py`, `log_parser.py`, `inventory.py`, `probe.py`, `ollama/client.py`) إلا بضرورة قصوى مبررة؛ الأفضل إضافات في وحدات جديدة.
7. أي تعديل على طبقة التخزين يوجب بندًا في `THREAT_MODEL.md` + اختبارًا مثبِّتًا. لا ترفع `SCHEMA_VERSION` أبدًا دون آلية ترحيل ذرية مُختبَرة على قاعدة v1 حقيقية (مؤقتة).
8. **تقارير بالأدلة:** صنّف كل بند `PROVEN` / `PARTIALLY_PROVEN` / `UNPROVEN` / `CONTRADICTED` / `BLOCKED`. لا تدّعِ تنفيذًا لم يحدث، ولا تقل "الثغرة أُغلقت" — قل "الخطر خُفِّض والنافذة المتبقية موثقة".
9. إن احتجت صلاحية أو قرارًا خارج حدودك، توقف واطلب موافقتي صراحةً.

## مهمتك الآن

اختر بندًا واحدًا من القائمة (أو ما أسميه لك لاحقًا)، وطبّقه كاملًا بجودة دمج:

**أ. تصدير/استيراد مجهّل للسجلات:** صيغة حزمة JSON باسم مستقر (مثل `records-export-YYYYMMDD.json`)، تصدّر حقول القوائم المسموحة فقط (بلا `created_at` كاملًا — سنة/شهر فقط أو بلا وقت، بلا `prefix_id` افتراضيًا)، مع تحقق مشدد عند الاستيراد يمر عبر `_prepare_record` نفسها، وحد أقصى للدفعة، واختبارات شاملة، وتحديث README/CHANGELOG.

**ب. محرك توصيات تكيفي للقراءة فقط:** يستعلم السجلات `PROVEN`/`PARTIALLY_PROVEN` عبر طبقة الاستعلام ويقترح خطوة تشخيص تالية (نص إرشادي ثابت من قاموس داخلي — لا يُنفّذ أي أمر أبدًا، لا يلمس Wine، والمخرجات اقتراحات فقط)، مع بيانات إدخال من `codes.py` و`vendor_data.py`، واختبارات، وتوثيق حدود "اقتراح لا حكم".

**ج. مراجعة أمنية/هندسية لـPR #4:** سألصق لك الفَرْق (diff)؛ راجعه سطرًا سطرًا: ثغرات، حالات حدّية، اتساق الأسماء، تغطية الاختبارات الناقصة، ودقة التوثيق — بمخرجات جدول: الموقع / الملاحظة / الخطورة / الإصلاح المقترح.

**د. توسيع خرائط رموز الأخطاء:** أضف أكواد HRESULT/NTSTATUS/Win32 موثوقة فقط (لا تخمين)، مع تعليق يشرح معنى كل كود، واختبار لكل إضافة، ومصدر معرفي عام (مثل توثيق Microsoft العام) يُذكر في التعليق دون نسخ كود.
